# FolderAdjuster

Windows用の日本語デスクトップツールです。Python 3.10以上（標準のTkinterを含む）が必要です。外部パッケージは不要です。

## 起動

EXE版はonedir形式です。ZIPをすべて展開し、`FolderAdjuster/FolderAdjuster.exe` を実行します。Pythonのインストールは不要です。`_internal` は必須の実行環境なので、EXEと同じ場所に保持してください。EXE単体を移動しないでください。

既存版から更新する場合は、アプリを終了して新しいZIPを別フォルダに展開し、旧EXEと同じ場所にある `settings.json` と `operation-history` を新しいEXEと同じ場所へコピーしてください。整理対象にある `.folder-tool-trash` も履歴復元に必要です。

以下はソース版の起動方法です。

Pythonをインストールして `start.bat` をダブルクリックします。コマンドからは `py -3 app.py` で起動できます。

## 2つの独立した作業

- 「フォルダ名変更・作成・移動」タブ：この作業用の親フォルダを選択し、括弧削除・名前編集・分類フォルダ作成・移動を行います。
- 「本の整理・リネーム」タブ：本の整理専用フォルダを別に選択し、巻数の名前変更・画像連番・画像以外の削除を行います。

対象フォルダの選択はそれぞれ独立して保持します。一方で選んだパスをもう一方の作業へ引き継ぎません。

選択パスは選ぶたびに、アプリ（`FolderAdjuster.exe` または `app.py`）と同じフォルダの `settings.json` に保存し、次回起動時にタブごとに復元します。起動時の作業ディレクトリには依存しません。設定を引き継ぐ場合は、このJSONもアプリと一緒に移動してください。書き込み可能なフォルダに展開して使ってください。保存した対象フォルダが削除されたり外付けドライブが未接続だったりする場合は、そのパスを表示して再選択を促します。起動時に名前変更・移動・削除を自動実行することはありません。

## 操作

### 指定文字列を含むファイルの削除

左の「フォルダ名変更・作成・移動」タブに検索用テキストボックスがあります。例えば `広告 サンプル .txt *.url` と入力して「削除対象を検索・確認」を押すと、いずれかの条件に一致したファイルを検索します。

- 半角スペースで区切った条件のOR検索です。ファイル名（拡張子を含む）を部分一致で検索し、大文字・小文字は区別しません。
- `.txt`、`*.txt` は拡張子指定として扱います。`.txt.bak` は `.txt` 指定には一致しません。`.tar.gz` のような複合拡張子にも対応します。
- 対象は左タブで選んだ親フォルダ内の全ファイルです。下位フォルダも検索します。フォルダ名や親パスの文字列では検索しません。
- 空欄では検索できません。リンクと復元用 `.folder-tool-trash` は対象外です。
- 縦長のスクロール一覧にファイルを列挙し、行をクリックして削除対象から解除・再選択できます。全選択・全解除もできます。
- 最終確認の後に選択したファイルを `.folder-tool-trash/files-固有ID/` へ退避し、元の場所から削除します。ディスク容量は解放しません。復元元は `restore.json` に記録します。
- 入力値はアプリと同じフォルダの `settings.json` に保存し、次回起動時に復元します。画像整理タブの対象パスには影響しません。

### フォルダ名変更・作成・移動

1. 「親フォルダを選択」で整理対象を指定します。直下のフォルダだけを扱い、ファイルやリンクは対象外です。
2. `(…) を削除`、`[…] を削除` を選びます。全角の `（…）`、`［…］` にも対応します。
3. 一覧の「元の名前」と下部の範囲調整欄で、削除予定の部分だけを赤くハイライトします。保護した部分には色を付けません。下部の赤い括弧部分をクリックすると削除を解除します。再クリックで削除に戻せます。残したいタイトルに含まれる `()` や `[]` も個別に保護できます。任意の文字範囲をドラッグして「選択範囲を残す」「選択範囲を削除」で細かく調整できます。範囲の調整は一覧にも反映し、その行の手動編集は自動の名前に戻ります。直接編集した行は変更後の名前との差分（削除・置換部分）をハイライトします。実行対象外の行は一覧のハイライトを消します。
4. 「変更後の名前」をダブルクリックして直接編集できます。Enterで確定、Escapeで取消。「実行」列をクリックすると行全体を対象外にできます。

編集中に一覧をスクロールした場合や、確認ボタンを押した場合も、入力を確定してから処理します。行を実行対象外にすると、一覧と下部のハイライトを両方消します。
5. 分類フォルダの作成・移動を選ぶと、元の名前にある最初の丸括弧の文字列を分類名の初期値に使います。名前の構成が違う場合は、一覧の「作成フォルダ名」をダブルクリックして変更するか、下部で文字範囲をドラッグして「選択範囲を作成フォルダ名にする」を押してください。範囲選択では括弧を含めた文字列もそのまま使用できます。空欄の場合はその行を分類しません。移動だけを選んでも必要な分類フォルダを作成します。
6. 「プレビューを確認して実行」で全変更を確認し、「この内容で実行」を押します。

例：`作品 (作者A) [完成]` と `別作品 (作者A)` は `作者A` フォルダにまとめられます。括弧削除も選んだ場合は `作者A/作品`、`作者A/別作品` になります。分類名は削除前の元の名前から取得します。

`[(文字列)]` は角括弧のひとまとまりとして削除・保護します。「丸括弧だけを削除」を選んでも、この角括弧の内側は残ります。分類名の取得は元の名前の丸括弧から行います。

同名の変更先がある場合は、双方のフォルダ内のファイル容量（子フォルダを含む、リンクは除く）とパスを表示し、削除する側を選べます。**容量が大きい側が削除候補として初期選択されます。** 同容量の場合は先に表示する側を選択します。容量はファイルのバイト数の合計で、ディスク上の占有量とは異なります。読み取りできない場合は処理を止めます。

選択確定だけでは削除しません。最後の実行確認後に、選んだフォルダを親フォルダ内の `.folder-tool-trash/固有ID/` へ退避します。元の場所からは削除しますが、ディスク容量は解放しません。Windowsのごみ箱への移動ではありません。「操作履歴・元に戻す」から復元できます。履歴がない場合は `restore.json` に記載された元の場所へ手動で戻してください。不要になった退避データはエクスプローラーから削除できます。退避フォルダは整理一覧から除外します。

空の名前、Windowsの禁止文字・予約名などは実行前に拒否します。処理中の失敗時は完了分の復元を試み、復元できなかった場合は画面に表示します。大切なデータはバックアップを取り、処理中にほかのアプリで対象フォルダを変更しないでください。その他の入れ子の括弧は内側の独立した括弧部分だけを対象にします。再読み込みすると編集・保護の選択は初期化されます。

## 感嘆符・疑問符の自動置換

削除後の名前と作成フォルダ名には、直接編集した場合も次の置換を適用します。結果は一覧と実行前プレビューに表示します。

- 単独の `!` → `！`
- 2つ以上続く感嘆符は全て半角：`！！` → `!!`、`!！!` → `!!!`
- 感嘆符と疑問符が連続する部分は全角：`!？` → `！？`、`？!` → `？！`。`!?`、`?!` も同様です。
- 混在する連続部分の全角化を優先：`!!？` → `！！？`
- 感嘆符を含まない疑問符はそのまま残します。

削除から保護した文字列にもこの置換を適用します。

## 別機能：画像を自然順で連番化

「本の整理・リネーム」タブで専用フォルダを選択し、「画像を自然順で連番化・画像以外を削除」を押します。次の構成の画像が対象です。

```text
選択した親フォルダ/
  タイトルA/
    本データ1/画像1.jpg、画像2.jpg、画像10.jpg
    本データ2/画像1.png、画像2.png
  タイトルB/
    本データ1/…
```

本データフォルダごとに自然順で `001` から連番を付け、拡張子（大文字・小文字も含む）は保持します。1000枚以上は `1000` 以降になります。数字が同じ場合は元の名前で順序を決定します。対象は jpg/jpeg/png/gif/bmp/webp/tif/tiff/avif/heic/heif/jxl。異なる形式もまとめて番号を付けます。

プレビューで全画像の変更前後と、画像以外の削除対象を確認してから実行します。本データフォルダ内の画像以外のファイルは、下位フォルダも含めて `.folder-tool-trash/images-固有ID/` に退避し、元の場所から削除します。完全削除ではなく、ディスク容量は解放しません。退避先の `restore.json` で復元元の場所を確認できます。対応拡張子で画像を判定するため、PDF・ZIP・テキストなども削除対象です。

リンクと下位フォルダ内の画像は変更しません。フォルダ自体は残します。親フォルダ直下・タイトル直下のファイルは削除しません。既に連番の画像があっても一時名を経由して上書きを防ぎ、失敗時は元の名前と退避ファイルの復元を試みます。実行中に他のアプリで対象を編集しないでください。

## 別機能：本フォルダにタイトル・巻数を付ける

「本の整理・リネーム」タブで専用フォルダを選択すると、本フォルダをタブ内の一覧に表示します。親タイトル・現在の名前・変更後の名前・推測した巻数を確認でき、変更後の名前はダブルクリックで編集できます。実行欄のクリックで対象から除外・追加できます。変更内容を調整してから「本フォルダにタイトル・巻数を付ける」または一覧下の確認ボタンを押します。タイトル直下の各本データフォルダを `親タイトル 第XX巻` に変更します。画像連番とは別の操作なので、必要な順序で実行できます。

- `ossan_wa_suro_raifu_no_v05s` → `親タイトル 第05巻相当`
- `rpeggio_of_Blue_Steel_Kaiyo_Gijutsu_v02` → `親タイトル 第02巻`
- `name_v05s_extra` → `親タイトル 第05巻相当`

フォルダ名の最も右にある連続した数字を巻数に使い、その直後の小文字 `s` だけを「相当」のトリガーにします。末尾の数字でなくても取得します。後ろに別の数字がある場合はそちらを優先します。1〜99は2桁（01〜99）、100以上は最低3桁（100、101…）にします。

数字なし・0巻は自動処理の対象外です。プレビューで変更後の名前をダブルクリックして編集でき、「実行」欄をクリックして対象へ追加・除外できます。同名衝突時は従来どおり容量を比較して削除側を選択し、大きい側を初期選択します。削除対象はタイトル内の `.folder-tool-trash/` へ退避します。タイトルごとに処理し、途中で失敗した場合は完了済みタイトルを表示します。

## 改善した操作

- 操作履歴：両タブの「操作履歴・元に戻す」から、完了した名前変更・移動・退避を取り消せます。履歴はアプリと同じ場所の `operation-history/*.json` に保存します。復元には履歴と退避データの両方を残してください。操作後のサイズ・更新日時などを照合し、変更されたデータや復元先の同名がある場合は停止します。直近の操作から順に戻してください。強制終了時の未完了履歴は要確認と表示し、自動復元しません。
- 進捗とキャンセル：読み込みと実行を別スレッドで処理し、確認・処理ステップ数を表示します。キャンセル時は安全な区切りで停止し、変更分の復元を試みます。本の巻数変更はタイトルごとに履歴を保存するため、完了済みタイトルは履歴から戻してください。
- 同名比較：容量、ファイル数、画像数、片側だけにあるファイル名の例を表示します。「削除する」「残す」を明示し、初期状態では容量が大きい側を削除候補にします。
- 削除プリセット：丸括弧・角括弧の削除設定、角括弧の対象範囲（すべて／先頭だけ／末尾だけ）、ファイル検索条件を名前付きで保存できます。先頭・末尾だけは該当する1組が対象です。行ごとの手動編集・保護範囲はプリセットに含めません。
- 絞り込み：メイン一覧は変更あり・同名衝突・実行対象、本の一覧は変更あり・巻数不明・同名衝突で表示を絞れます。表示だけの絞り込みです。非表示の行も実行チェックが付いていれば実行対象です。
- 巻数の確認：本フォルダ一覧の元の名前で、取得した数字と直後の `s` を黄色で表示します。
- アプリ名とアイコン：FolderAdjusterとして、作成したフォルダアイコンを採用しています。

## Windows EXEを作る

WindowsでPython 3.12を用意し、`build-windows.bat` を実行すると `dist/FolderAdjuster/FolderAdjuster.exe` を作成します。ビルド時のみPyInstallerをインストールします。GitHub Actionsの「Build Windows application」でもテスト・EXE作成・起動確認・ZIP配布を実行します。

本の一覧は対象パスの復元時にも読み込みます。「一覧を再読み込み」で現在の構成を取得し、手動編集・対象解除・表示絞り込みを初期化します。名前変更の実行後、画像整理の完了後、履歴からの復元後も一覧を更新します。絞り込みは表示だけで、非表示の実行チェックも維持します。一覧の実行チェックは本フォルダ名の変更用です。画像整理は選択した本整理フォルダ全体を対象に、別の確認一覧から実行します。

本整理の同名衝突フィルターは実行対象の予定名を比較します。途中キャンセルした場合は完了済みタイトルを表示します。関連操作は新しい履歴から順に戻せます。ファイルの変更や項目の追加・削除は復元前に検出します。古い版の履歴に復元用の状態記録が不足している場合、アプリは復元を停止します。

本整理で名前変更・削除に失敗した場合は、使用中・アクセス拒否・名前の長さなどの原因、対象と移動先を表示します。使用中のファイルは短時間だけ自動再試行します。ロックが続く場合は画像ビューアーやエクスプローラーのプレビュー等を閉じて再実行してください。失敗の詳細はアプリ横の `operation-errors.log` に保存します。権限変更や使用中のアプリの強制終了は行いません。

同名フォルダの削除（退避）には短い識別子を使用します。元の名前と退避先の対応は `restore.json` に記録し、操作履歴から復元できます。新しい名前がWindowsの上限（UTF-16で255単位）を超える場合は、退避を開始する前に拒否します。

画像以外のファイルも、長いパスを繰り返さないよう退避先には短い数値IDを使います。元のファイル名・場所はrestore.jsonに保存します。復元は「操作履歴・元に戻す」から実行できます。

## AttendSyncの監査体制

AttendSyncには12専門役と統括役による監査設定を追加しています。Codexで「通常監査して」「完成監査して」「修正後監査して」と指示できます。[呼び出し方と設定の説明](docs/audit/README.md)を参照してください。監査中の製品修正は行いません。
