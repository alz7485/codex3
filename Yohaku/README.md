# 余白 / YOHAKU

<img src="companion/assets/app/yohaku.png" width="112" alt="余白のアイコン">

**仕事に、ひと呼吸。** 予定とファイル履歴をそっと知らせる、デスクトップの小さな同僚です。

[ソースZIPをGitHubからダウンロード](https://github.com/alz7485/codex3/raw/refs/heads/main/downloads/Yohaku/Yohaku-v0.6.1-source.zip)

v0.6.1ではアプリ名と固定アイコン、Windows onedir用spec・ビルドコードに加え、ターミナルへ直接貼り付ける `ONEDIR_COMMAND.txt` を同梱しました。ダウンロードZIPには完全なソースと素材が入っています。**ビルド済みWindows EXEは含みません。**

Windowsデスクトップの隅で、予定と短いひとことをそっと知らせる常駐アプリの試作品です。**画面下での歩行・表情アニメーション・音声なし・従来版Outlook**に対応しています。

v0.5ではクリック時に**「お呼びですか？」「用事は何でしょう？」「何？」のような問いかけ＋縦4行の選択肢**を出します。問いかけは性格に応じて変わり、通常の雑談とは分けています。

- キャラをクリック → 問いかけの下に、上から「予定を聞く」「ファイル起動履歴を見る」「設定を開く」「一言を聞く」を1行ずつ表示します。
- 「予定を聞く」と「一言を聞く」は、同じ吹き出し内の文章を更新します。4つの選択肢は下に残ります。
- 「ファイル起動履歴を見る」はカレンダーとファイル一覧の専用ウィンドウ、「設定を開く」は設定画面を開きます。右クリックメニューからも設定を開けます。
- 「キャラと通知」でアニメーションと歩行を個別設定できます。初期設定はオンです。歩行をオフにすると、現在位置で表情だけが動きます。
- ファイル履歴は初期設定オフ。設定でオンにすると、ファイル名・保存先・検出時刻をこのPCに記録します。7日間・最大1,000件。「保存した履歴をすべて削除」で消せます。

採用キャラは **A：余白ノート / B：事務ロボ / E：まじめなペンギン / F：お茶ねこ** です。「キャラと通知」の先頭にあるサムネイルをクリックすると、常駐キャラ・操作画面・トレイアイコンが即時に切り替わります。選択は自動保存され、次回起動時にも引き継ぎます。初期設定はAです。性格は見た目と独立して選べます。

見た目の切り替えではOutlookの接続状態・取得中の処理・表示中の通知・おやすみ・画面共有モード・重複通知の履歴を変更しません。v0.1の設定ファイルもそのまま読み込めます。キャラの指定がない、または不正な場合はAを使用します。

会社のデスクトップで目立ちすぎない小さなキャラクターです。AI API、音声、効果音、広告、利用状況の送信、自動アップデートはありません。キーボード・マウスの操作履歴は収集しません。アプリ自身に外部送信用のクライアントはありません。Outlook自体の同期動作はOutlookの設定に従います。

## Windowsで起動する

対象は **Windows 11 / Python 3.11 または3.12 / 従来版Outlook** です。これはソースコードのZIPです。Windows用EXEは含んでいません。

1. ZIP全体をユーザーが書き込める場所へ展開します。
2. Python 3.11または3.12が導入済みの環境で `SetupAndRun.cmd` を実行します。初回はPySide6とpywin32をダウンロードします。管理者権限は不要です。
3. 右下にキャラクターと操作画面が現れます。接続前でも「通知を試す」で見た目を確認できます。このボタンは静かな時間・おやすみ設定にかかわらずプレビューを表示します。画面共有モードでは表示しません。
4. **従来版Outlookを起動してから**「Outlookに接続」を押します。最初の接続後は、次回起動から自動で再接続します。切断はトレイメニューから行います。
5. 操作画面を閉じてもキャラクターとトレイは残ります。終了はキャラの右クリック、またはトレイの「余白を終了」です。
6. キャラをクリックすると普段の吹き出しに問いかけと4行の選択肢が出ます。設定画面・履歴ウィンドウ・吹き出し・通知を閉じると、しばらくして画面下を歩き始めます。初期設定の静かな時間（18:00〜翌09:00）は動きません。動作を試す場合は、静かな時間の開始と終了を同じ時刻にしてください。

会社の端末では、Python実行・依存パッケージ導入・Outlook COM利用について、その会社の通常の導入ルールを適用してください。制限を迂回する機能はありません。

手動で起動する場合：

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

導入時のダウンロードが認められていない環境では、管理担当者が用意した適合するwheel群から `pip install --no-index --find-links <wheelフォルダー> -r requirements.txt` で導入できます。実行時のAI用キー・外部サービスの認証は不要です。

## 小さなMVPの動作

- キャラクターはプライマリ画面の右下から開始し、タスクバーを避けた画面下の範囲を歩きます。最初は約15秒待ち、その後は25〜55秒ほどの間隔で70〜160pxを毎秒20px程度で移動します。画面端で折り返します。上方や作業画面の中央へは移動しません。
- A/B/Eは2コマの足踏み、Fは湯のみごとの揺れで移動します。待機中に短いまばたき、クリック・メッセージ時に笑顔、予定通知時にお知らせの表情になります。静かな時間・おやすみ・画面共有モード中はアニメーションを停止します。設定画面・吹き出し・通知の表示中、キャラにポインターを乗せている間は歩行を止めます。
- 普段の通知とクリック時に同じ幅322pxのしっぽ付き吹き出しを使います。クリック時は問いかけの下に4つの選択肢を縦に並べます。タブやカレンダーを吹き出し内に置かず、「予定を聞く」「一言を聞く」で別画面を開きません。クリックの吹き出しは自動で閉じず、「×」またはEscで閉じます。予定は最新の取得結果から10件まで表示し、長い場合はスクロールできます。
- 履歴の専用ウィンドウはカレンダー＋ファイル一覧で、その日ごとに200件まで表示します。メッセージ・予定を選んでも、開いている履歴ウィンドウはそのまま残ります。閉じても常駐アプリは終了しません。雑談の自動発言は吹き出し操作を待ちますが、予定開始前の通知は優先して表示します。
- 従来版Outlookの既定予定表から当日の予定を2分ごとに読み取ります。読み取りは別スレッドで、UIを止めずに行います。予定の作成・変更はしません。
- 開始10分前から開始直前までに取得できた予定を、1つの開催回につき1回知らせます。アプリ停止中の予定通知は行えません。通知を見送ったまま開始時刻を過ぎた場合は後追いしません。
- 繰り返し予定は開催日時を含むキーで区別します。終日予定、キャンセル済みの予定は対象外です。今日より前に開始した複数日予定もMVPの通知対象外です。
- 接続失敗時は予定通知を止め、キャラクターと雑談を利用できます。前回取得から5分以上経った予定データでは通知しません。
- 雑談は初期設定で90分に1回まで。予定通知を優先し、取得済みの予定の開催中は雑談を控えます。入力監視や在席判定は行わず、起動・発言からの経過時間を使います。
- 性格は4種。直近2回と同じセリフを避けます。発言集は `companion/core.py` の `PHRASES` で編集できます。
- 静かな時間は初期設定で毎日18:00〜翌09:00。予定通知も雑談も停止します。同じ開始・終了時刻を設定すると時間帯指定を解除します。
- 「1時間おやすみ」は予定通知も雑談も停止します。途中解除が可能です。再起動で解除されます。
- 「画面共有モード」はキャラ・吹き出し・操作画面・履歴ウィンドウを隠して自動発言を停止します。トレイから解除できます。画面共有を自動検知する機能ではありません。トレイから操作画面を明示的に開くことはできます。トレイを使えない環境ではこのボタンを無効にします。
- 予定通知は14秒、雑談は10秒で閉じます。フォーカスを奪いません。小さな「×」でも閉じられます。
- 同一ユーザーでの二重起動をロックファイルで防ぎます。Windowsのスタートアップへの登録は行いません。

初期状態では予定件名を取得・表示しません。明示的に件名表示をオンにした場合のみ件名も読み取り、画面と通知に表示します。オフに戻すと表示・キャッシュを直ちにクリアし、進行中の古い取得結果も破棄します。出席者、本文、添付ファイルは読み取りません。

## 保存内容

保存先：`%LOCALAPPDATA%\Yohaku`

| ファイル | 内容 |
|---|---|
| `settings.json` | キャラ（A/B/E/F）、歩行・アニメーション、ファイル記録、性格、頻度、静かな時間、件名表示、Outlook再接続設定 |
| `history.json` | セリフの識別子、重複通知防止のためのSHA-256キーと保持期限 |
| `files.sqlite3` | 記録をオンにした場合のファイル名・保存先・取得元・検出時刻・確認時刻（UTCで保存、画面ではローカル時刻） |
| `instance.lock` | 二重起動防止用のロック |

予定件名・本文・出席者・生の予定IDはファイルへ保存しません。キーは開催回終了の翌日を過ぎたら、次の履歴保存時に削除します。保存ファイルは暗号化せず、Windowsのユーザーフォルダーのアクセス制御を利用します。初期化するときはアプリ終了後、このフォルダーを削除してください。

### ファイル履歴の範囲と日付選択

キャラの吹き出しで「ファイル起動履歴を見る」を選ぶと専用ウィンドウが開きます。左側のカレンダーから過去7日間の日付を選択し、「今日に戻る」で当日へ戻れます。その日の記録を最大200件、ファイル名・完全な保存先・時刻・取得元付きで表示します。長い保存先は行にポインターを置くと全文を確認できます。記録のない日は「この日の記録はありません」と表示します。同名でも保存先が違うファイルは別々に記録します。記録オフのままでも保存済み履歴の日付を選んで閲覧できます。

取得元は、既に起動しているExcel・Word・PowerPointの文書一覧と、Windowsの「最近使ったファイル」のショートカットです。Officeを起動したり、文書を開いたり、本文を読んだりはしません。取得できるOfficeインスタンスのみ対象で、複数インスタンスの全件取得は保証しません。最初に取得できた開いているファイルと既存の最近使ったファイルを基準にし、その後の変化を記録します。オンにする前の履歴を遡って取り込む機能はありません。

5秒間隔なので短時間の開閉は見逃す場合があります。Officeが応答しないとき、Windowsが履歴を残さないソフト、最近使ったファイルの記録が無効な環境、ブラウザー内の文書、未保存の文書等は記録できない場合があります。これは網羅的なファイル操作監査ではありません。Officeは新しく一覧に現れたファイル、Windowsは最近使ったファイルの更新を検出するため、表示する時刻は初回確認またはショートカット更新の時刻です。保存先の変更も別ファイルとして記録される場合があります。同じファイルの複数取得元からの通知や15秒以内の再検出は1件にまとめます。開き直しは閉じた状態と再表示を確認できた場合に記録します。

**ファイル名と完全な保存先を保存します。** 文書の内容、キーボード入力、起動コマンド、予定件名は履歴に保存しません。ショートカットの参照先の文書・ネットワークパスを読み込んで確認する処理も行いません。ファイルを開いたり、移動・削除したりする機能はありません。

オフにすると新しい確認と記録を停止します。保存済み履歴は閲覧・削除できます。履歴削除は進行中の古い確認結果も破棄し、記録オンなら新しい基準から再開します。期限切れは起動後の定期処理、1時間ごとの整理、履歴の読み書き時に削除します。アプリ終了中の期限切れは次回起動時に整理します。画面共有モード中も、記録がオンなら記録は継続します。

## Windows用配布フォルダーを作る

Windows 11 / 64bit Python 3.11または3.12で、展開した`Yohaku`フォルダーをターミナルで開き、同梱の **`ONEDIR_COMMAND.txt`** のコマンドを順に貼り付けて実行します。バッチ・PowerShellスクリプト・仮想環境の有効化は使いません。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean Yohaku.spec
.\.venv\Scripts\python.exe scripts\collect_licenses.py dist\Yohaku
.\.venv\Scripts\python.exe -c "import shutil; shutil.make_archive('Yohaku-v0.6.1-windows-x64-onedir', 'zip', 'dist', 'Yohaku')"
```

Python 3.12の場合は、1行目を `py -3.12 -m venv .venv` に変更します。

3行目がonedirを作るコマンドです。`Yohaku.spec`にフォルダー形式、アイコン、4キャラとアニメーション素材、製品名・版を定義しています。出力は `dist\Yohaku\Yohaku.exe`。5行目で作るZIPは作業フォルダー直下の `Yohaku-v0.6.1-windows-x64-onedir.zip` です。

| 同梱ファイル | 用途 |
|---|---|
| `ONEDIR_COMMAND.txt` | ターミナルへ貼り付ける直接コマンド |
| `BuildWindows.cmd` | バッチが利用できる環境向けの補助入口 |
| `scripts/build_onedir.py` | 仮想環境の準備、PyInstaller、素材の確認、配布ZIPの作成 |
| `Yohaku.spec` | onedir用の定義。4キャラ・アニメーション・アプリアイコンを同梱 |
| `packaging/windows_version_info.txt` | 余白 / YOHAKUの製品名とバージョン情報 |
| `scripts/package_source.py` | 完全ソースZIPとSHA-256の作成。ローカルの設定・履歴を除外 |
| `.github/workflows/yohaku-windows.yml` | GitHub ActionsのWindowsビルド定義 |

依存の導入から配布ZIPまでPythonのビルドヘルパーに任せる場合は、次のコマンドも使えます：

```powershell
py -3.11 scripts/build_onedir.py
```

ビルドヘルパーの場合の出力は `dist\Yohaku\Yohaku.exe` と `release\Yohaku-v0.6.1-windows-x64-onedir.zip` です。**EXEだけを取り出さず、ZIPをすべて展開して実行してください。** DLL・Qt・画像は同じフォルダーの`_internal`に入ります。配布物には依存ソフトウェアのライセンス文書もコピーします。署名・社内パッケージ化は含みません。LinuxからWindows EXEを作ったものではありません。

ビルド素材の確認だけなら `python scripts/build_onedir.py --check`、ビルド環境の準備だけなら `py -3.11 scripts/build_onedir.py --setup-only` を使います。Windows用ビルドはWindows上で実行してください。

### GitHubからダウンロードする

- ソースZIP：上のダウンロードリンク、または `downloads/Yohaku/` の案内から取得します。
- コード：`Yohaku/` に同じ完全ソースを置いています。
- GitHub Actions：リポジトリの「Actions」→「Build YOHAKU Windows onedir」→「Run workflow」でWindowsビルドを実行できます。成功後の「Artifacts」からonedir ZIPとソースZIPを取得します。
- このプロジェクトを別のリポジトリに置く場合は、同梱の`.github/workflows/yohaku-windows.yml`を**リポジトリ直下**の同じパスに置いてください。ワークフローはリポジトリ直下、または`Yohaku/`にあるソースを検出します。

## 検証

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

LinuxのQt offscreen環境で42件の自動テストが通過しています。既存の通知・履歴・アニメーション、問いかけと4行の選択肢に加え、アプリ名・固定アイコン、onedirに必要な素材、完全ソースZIPのハッシュ一致、設定・履歴等がZIPに入らないことを確認しました。プレビュー画像は実際のQtウィジェットから生成しています。`preview_animation.py` はFFmpegがあればGIFも書き出します（アプリ実行時には不要です）。

キャラクター画像は `companion/assets/characters/` の背景透過PNGです。画像は開発時に作成した静的な素材で、アプリの起動・切り替えでAIや画像生成サービスに接続しません。Windowsビルドのバッチも、このフォルダーを配布物へ含める設定に更新しています。

**Windows実機・Office文書一覧・Windows最近使ったファイルの取得・実Outlook COM・高DPI・複数画面・Windows通知領域・EXEのビルドと動作は、このLinux環境では未検証です。** `docs/WINDOWS_CHECKLIST.md` に確認手順を記載しています。新しいOutlookのみの環境には対応していません。
