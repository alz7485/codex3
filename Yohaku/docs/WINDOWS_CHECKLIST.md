# Windowsでの確認手順

このチェックは未実施です。社内環境での利用可否の認定を意味しません。合成予定や個人情報を含まないテスト予定表で確認してください。

1. Windows 11とPython 3.11/3.12で依存関係を導入し、READMEの直接コマンドで起動する。
2. 100%・150%・200%表示で文字やボタンが切れないか、設定ページをスクロールできるか確認する。
3. キャラがタスクバーを避けて表示され、吹き出しが操作中のアプリからフォーカスを奪わないことを確認する。
4. 画面の抜き差し、プライマリ画面の変更、タスクバー位置変更でキャラが画面内に残ることを確認する。
5. 従来版Outlookを開き、接続する。日本語・英語など実環境のWindows地域設定で日付フィルターが機能するか確認する。COM権限が拒否された場合は接続失敗が表示されることを確認する。
6. 10分後以内に始まるテスト予定を作り、2分以内の再取得後に一度だけ通知されることを確認する。予定の件名は初期状態で表示されないことを確認する。
7. 同じ開催回でアプリを再起動して重複しないか、翌開催回の繰り返し予定は通知されるか確認する。例外変更・キャンセルした開催回、終日予定、複数日の予定も確認する。
8. WindowsとOutlookのタイムゾーンが異なる環境や夏時間の境界付近で、StartUTCの変換と通知時刻を確認する。
9. 件名表示をオン→オフにし、表示・吹き出しから即時に件名が消えること、history.jsonに件名が入らないことを確認する。
10. おやすみ・静かな時間・画面共有モード中に自動通知が出ないことを確認する。画面共有モード解除と終了はWindowsのトレイから行う。
11. Outlookを終了・切断し、エラー時に以前の予定が通知されないことを確認する。Outlook起動後の再接続も確認する。
12. スリープ・復帰後、開始済みの予定が後追い通知されないこと、静かな時間が正しく適用されることを確認する。
13. 二重起動が防止されること、終了後に再起動できることを確認する。
14. ONEDIR_COMMAND.txtの直接コマンドでonedirを作り、Pythonがインストールされていない別のテスト端末でフォルダー全体から起動確認する。
15. 「キャラと通知」でA/B/E/Fを順に選び、常駐キャラ・操作画面・トレイアイコンが即時に切り替わることを確認する。再起動後も選択が残り、「キャラクターに合わせる」では固有の性格になり、個別指定した性格は保持されることを確認する。
16. Outlook接続中・取得中・通知表示中・おやすみ中・画面共有モード中にキャラを変え、接続や通知履歴が失われず、非表示中のキャラが勝手に再表示されないことを確認する。EXEにも4種すべての画像が同梱され、背景が透過されるか確認する。
17. A/B/E/Fの待機・まばたき・笑顔・お知らせ・歩行を確認する。Fは湯のみごと揺れて移動する。静かな時間の外で設定画面を閉じ、約15秒後以降の歩行を確認する。
18. キャラを右クリックして「お呼びですか？」等の問いかけの下に、「予定を聞く」「ファイル起動履歴を見る」「設定を開く」「非表示にする」が縦4行で出ることを確認する。一言は左クリックで表示し、予定も同じ吹き出し内で返し、履歴と設定はそれぞれ専用画面を開くことを確認する。約1分で閉じ、×・Escは吹き出しだけを閉じること、呼び出しの「非表示にする」はキャラごと非表示にすることも確認する。
19. 初期設定オフではOffice文書一覧や最近使ったファイルの取得を行わず、files.sqlite3を作らないことを確認する。オンにしてから保存済みExcelブックを開き、ファイル名と完全な保存先が記録されることを確認する。Word・PowerPointも確認する。
20. 同名で保存先が違うファイル、閉じて20秒以上後に開き直すファイル、複数Officeインスタンス、Officeが応答しない状態、ネットワーク共有上のファイル、最近使ったファイルの記録が無効な状態を確認する。取得漏れがある条件を記録する。本文や入力内容は保存されないことを確認する。
21. カレンダーから昨日・今日・記録のない日を選び、選択した日の記録だけが表示されることを確認する。深夜と夏時間の境界付近でも日付が混ざらないか確認する。
22. 記録をオフにして取得が止まること、保存済み履歴は閲覧できること、削除後に古い取得結果が戻らないことを確認する。7日間・1,000件の保持制限も確認する。

Outlookの読み取りが社内設定で制限されている場合は、設定を変更したり認証を回避したりせず、接続なしのキャラクターとして利用するか、社内の導入担当者に確認してください。

23. キャラ・吹き出し本文を右クリックして呼び出しを出し、「非表示にする」でキャラと吹き出しが隠れ、通知領域のアイコンは残ることを確認する。アイコンの左クリックでキャラだけを戻し、再度左クリックで非表示、右クリックで設定・終了を選べることを確認する。
24. 静かな時間外に約10分待ち、約1分表示される自動会話を確認する。手動で一言を聞いた後は次の自動会話が約10分後になること、会議中・非表示・設定操作中には自動雑談を出さないことを確認する。
25. 朝・昼・午後・夕方、月曜・金曜・週末、予定の前後の定型文を確認する。4キャラを切り替え、固有の言葉遣いと話題に合った表情が出ることを確認する。旧設定からの移行で間隔が一度だけ10分に変更され、その後選んだ間隔が保持されることも確認する。
26. 約60fpsを目安に歩行の8コマ、加減速、待機時の呼吸としぐさが滑らかに見えるか、CPU使用率が社内端末で許容範囲か確認する。画面スケーリングとスリープ復帰後も大きく飛ばないことを確認する。

27. 「キャラと通知」→「会話文・発生ルールを編集」、およびトレイの「会話を編集」で編集画面を開く。日本語・改行入りのセリフ、独自話題、時間帯・曜日・予定前後、表情、会話間隔、吹き出し秒数を変更し、「保存して反映」で次の会話に反映されること、再起動後も保持されることを確認する。
28. 空のセリフや不正な条件では保存できず、動作中の会話が変わらないことを確認する。保存先を書き込み不可にした場合のエラーと内容保持、JSONの入出力、初期値へのリセット、バックアップからの復元も確認する。
29. 未保存の編集を閉じる・終了すると保存／破棄／キャンセルを選べ、キャンセルで編集が残ることを確認する。非表示・画面共有では編集画面も隠れ、開き直すと編集中の内容が残ることを確認する。

30. Windowsで操作を止めた時間と操作あり推定時間、日別累計、日跨ぎ、スリープ復帰を確認する。アプリ停止・計測できない時間を足さず、初回起動で「昨日使っていない」と言わないことを確認する。usage.jsonには各日の集計と使用日だけがあり、入力内容やファイル名が入らないことも確認する。
31. 取得可能なOffice文書数、ユーザーとPublicのデスクトップ件数、履歴オン時の同じ保存先の開き直し回数を確認する。取得失敗・古い値をゼロ扱いにしないこと、勤務時間が08:30〜17:30として条件に反映されること、今週と当日の予定数も確認する。
32. 従来版Outlookに接続し、テスト用メールと会議依頼を受信する。受信イベントで通知され、イベントが使えない場合も約1秒の確認で検知すること、既存メールは出さないこと、同じ受信でイベントと確認の二重通知をしないことを確認する。件名の初期非表示・切り替え、本文や送信者を取得しないことも確認する。
33. 予定の淡い黄、新着の淡い青、会話の白、呼び出しの薄緑を確認する。新着が10分の会話間隔や呼び出し操作を待たないこと、非表示・共有・おやすみ・静かな時間中は表示せず復帰後にもまとめて出さないことを確認する。
