# PC状態の会話条件とOutlook受信通知

左クリックは一言、右クリックは呼び出しです。呼び出しは「予定を聞く」「ファイル起動履歴を見る」「設定を開く」「非表示にする」の4行。メッセージの選択肢はありません。

## 集計の範囲

| 情報 | 取得・保存の範囲 |
|---|---|
| 操作なし時間 | Windows GetLastInputInfoで最後の入力からの経過秒数を取得。入力内容・クリック位置・キー列は取得しない |
| 操作あり・なしの時間 | 初期は最後の入力から60秒未満を操作ありとして5秒ごとに推定。しきい値はJSON編集で変更可能。実際の作業時間ではない |
| 日別累計 | アプリ起動中に確認できた時間だけ。アプリ停止・計測できない間・15秒超のサンプル間隔は加算しない。日跨ぎは日別に分ける |
| Office文書数 | 既に起動している取得可能なExcel・Word・PowerPointの文書のCount。未保存文書を含む。他アプリやOffice全インスタンスの網羅ではない |
| デスクトップ件数 | Windowsのユーザーのデスクトップ（リダイレクト先を含む）とPublic Desktopのファイル数。ショートカットを含み、フォルダー内を再帰走査しない。隠し・システムファイル等は除外。最大10,000件 |
| ファイルを開いた回数 | ファイル履歴オン時だけ、その日の記録から同じ保存先ごとに集計。最も多いファイルの名前と回数を使う。検出漏れや15秒以内の重複除外があり、厳密な監査回数ではない |
| アプリの使用日 | このアプリを起動した日・動作中に日を跨いだ日を記録。初回は前日の情報がないため「昨日使わなかった」と発言しない |
| 今週・今日の予定件数 | 従来版Outlookの既定予定表。今週は月曜〜日曜、時間指定の予定のみ。キャンセル・終日予定は除外。上限512件の走査で未完了なら件数を不明として扱う |

日別の操作あり／なし／計測時間と使用日は `%LOCALAPPDATA%\Yohaku\usage.json` に35日間保存します。このファイルにファイル名・デスクトップの項目名・入力内容は保存しません。PC状態集計は設定からオフにでき、既存の集計を削除するボタンもあります。アプリ自身の使用日は集計オフでも記録します。ファイルの開き直しの会話は、従来どおりファイル履歴をオンにした場合だけです。

Office文書数・デスクトップ件数は約1分ごと、操作時間は5秒ごとに確認します。Officeが応答しない等で取得できないときは不明値にします。3分以上古いファイル件数、5分以上古い予定件数は会話に使いません。PCの操作が少ないことを、仕事をしていないと断定するセリフにはしません。

## JSON条件の初期値

全体の勤務時間は **08:30〜17:30**。編集画面の「全体設定・性格」で変更できます。休日カレンダーは参照せず、始業・終業に関する初期ルールは月〜金です。

| 話題 | 初期条件 |
|---|---|
| 操作がしばらくない | 5〜15分 |
| 長めに操作がない | 15分以上 |
| 操作が長く続く | 操作あり推定時間が45分以上連続 |
| 今日は操作が多い | 操作あり累計360分以上、計測も360分以上 |
| 今日は操作が少なめ | 14:00〜17:30、計測120分以上、操作あり累計60分以下 |
| Office文書が多い／少ない | 10個以上／2個以下 |
| デスクトップがにぎやか／すっきり | ファイル50個以上／10個以下 |
| 始業前 | 月〜金、始業まで0〜60分 |
| 定時まで数時間／もうすぐ定時 | 月〜金、定時まで60〜180分／0〜59分 |
| 定時後 | 月〜金、定時から15〜240分 |
| 同じファイルを何度も開く | 今日3回以上の記録 |
| 昨日アプリを使っていない | 過去の記録はあるが前日の使用日記録がない |
| 今週の予定が多い／少ない | 20件以上／5件以下 |
| 今日の予定が多い／少ない | 6件以上／1件以下 |

これらは発言候補の条件です。該当したら必ずすぐ話すのではなく、通常の約10分の会話間隔・話題の再発言間隔・抽選に従います。メール受信通知はこの間隔を待ちません。

「PC・ファイル・予定の集計値」の `metric_range` で下限以上・上限以下を指定できます。`maximum: null` は上限なし。不明値を0件に置き換えません。AND/ORは `all` / `any` と `conditions` 配列を使用します。

```json
{
  "kind": "all",
  "conditions": [
    {"kind": "weekday", "days": [0, 1, 2, 3, 4]},
    {"kind": "metric_range", "metric": "until_work_end_minutes", "minimum": 0, "maximum": 60}
  ]
}
```

集計値ID：`idle_minutes`、`active_streak_minutes`、`daily_active_minutes`、`daily_idle_minutes`、`observed_minutes`、`open_office_files`、`desktop_files`、`until_work_start_minutes`、`until_work_end_minutes`、`after_work_end_minutes`、`file_open_count`、`missed_yesterday`（1＝はい）、`days_since_last_use`、`weekly_events`、`daily_events`、`next_event_minutes`。

本文に `{idle_minutes}` などの同名の差し込みを使用できます。数値は丸めて表示します。加えて `{file_name}`、`{hours_to_end}`、`{work_start}`、`{work_end}`、受信通知の `{mail_count}` を用意しています。差し込みは文字列の置換だけで、コードを実行しません。

## 受信を検知したらすぐ表示

「Outlookに接続」し、設定の新着通知がオンなら、従来版OutlookのNewMailExイベントでメール・会議依頼を検知してすぐ通知します。イベント接続が使えないときも、受信トレイを1秒間隔で確認します。接続時点の既存メールは通知しません。イベント経由と受信トレイ確認の重複を除外します。

Outlookを勝手に起動しません。本文・送信者・添付ファイルを読まず、既読に変更したりメールを開いたりもしません。件名は初期非表示です。明示的にオンにした場合だけ画面表示用に読み、保存しません。メール識別子はメモリ内の重複除外に使うだけで、ファイルに保存しません。

予定の吹き出しは淡い黄、新着は淡い青、一言は白、呼び出しは薄緑です。新着通知は現在の会話や呼び出しを更新してすぐ表示し、フォーカスを奪いません。5秒以内に届いた追加分は表示件数にまとめます。

非表示・画面共有・おやすみ・静かな時間中は通知を見送ります。復帰後にまとめて表示しません。アプリ停止中や再接続の間に届いたメールの後追いは行いません。イベント通知されない仕分け先のメールや、受信トレイの上位100件に入らない大量受信を全件保証するものではありません。Teams等の他アプリ、OS全体の通知、新しいOutlookのみの環境は対象外です。

Windows実機・実Office・実Outlookのイベント配信はこのLinux環境では未検証です。自動テストでは合成データとCOMのモックで検知・重複除外・既存メールの無視・通知タイミング・色・抑制を確認しています。
