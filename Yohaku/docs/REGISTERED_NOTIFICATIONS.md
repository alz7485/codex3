# 自分で登録する通知

「キャラと通知」→「自分で登録する通知」→「通知を登録・編集」、またはトレイの右クリックメニューから開きます。「追加」で管理用の名前・条件・時刻・メッセージを入力し、「保存して反映」を押します。初期状態は登録0件です。100件まで登録でき、個別に無効化・削除できます。

| 条件 | 通知する日 |
|---|---|
| 毎日 | 毎日 |
| 毎週・曜日を指定 | 選択した曜日。複数選択可能 |
| 毎月・日付を指定 | 指定した日。31日などが存在しない月は月末日 |
| 月末の最終平日 | 月末日が月〜金ならその日。土日なら直前の金曜 |
| 毎月○日までの最終平日 | 基準日を含めて、それ以前の最後の月〜金 |

例えば2026年10月末は31日が土曜なので **10月30日（金）**。15日締めなら、2026年8月15日（土）は **8月14日（金）**、11月15日（日）は **11月13日（金）** になります。編集画面に次回対象日と時刻を表示します。無効な通知でも日付の試算ができます。

**平日は月〜金です。日本の祝日や会社独自の休日は除外しません。** 基準日がその月にない場合は月末を基準にして繰り上げます。「1日までの最終平日」で1日が土日なら、対象日は前月になります。

通知は青い吹き出しで、入力したメッセージだけを表示します。管理用の名前や見出し、×は付けません。通常と同じ表示時間（初期60秒）で閉じ、本文クリックでも閉じられます。勤怠サイトの選択・PC起動時間を付ける既存の退勤前通知は、従来の設定から別に登録します。

15秒ごとの判定で、対象日の指定時刻から10分以内に1回だけ表示します。再起動しても同じ通知ID・同じ対象日の二重表示を防ぎます。既存の吹き出しや未確認の連打反応を読み終わるまで待ち、同時刻の複数登録は1件ずつ表示します。予定開始前の通知と退勤前通知を優先します。待っている間に10分が過ぎた登録は後追いしません。

アプリ停止中は通知できません。非表示・画面共有・おやすみ・静かな時間中は抑制します。抑制を解除した時点で指定時刻から10分以内なら表示できます。初期の静かな時間は18:00〜翌09:00なので、その時間に通知したい場合は静かな時間も調整してください。Outlook接続や自動雑談をオフにしても、この登録通知は利用できます。

## JSON

`%LOCALAPPDATA%\Yohaku\reminders.json` に条件とメッセージを保存します。UIの保存後に即反映し、直前の内容を `reminders.json.bak` に残します。JSONを外部で直接編集した場合は、アプリを再起動して読み込みます。保存前の編集や保存に失敗した内容は、動作中の通知を変更しません。読み込み時に壊れたJSONがあれば登録通知を停止し、元のファイルとエラーを保持します。

```json
{
  "schema_version": 1,
  "notifications": [
    {
      "id": "month-end-check",
      "name": "月末の確認",
      "enabled": true,
      "time": "16:30",
      "message": "月末の確認をお願いします。",
      "condition": { "kind": "month_end_weekday" }
    },
    {
      "id": "cutoff-15",
      "name": "15日締めの確認",
      "enabled": true,
      "time": "15:00",
      "message": "締め日です。申請を確認してください。",
      "condition": { "kind": "monthly_weekday_before", "day": 15 }
    }
  ]
}
```

`daily` は追加項目なし、`weekly` は `weekdays: [0, 1, 2, 3, 4]`（月=0〜日=6）、`monthly_day` は `day: 1〜31` を条件に指定します。`id` は重複しない英数字・ハイフン・下線の64文字以内です。UIでは自動発行します。名前は80文字、メッセージは改行を含め1,000文字まで。時刻は `HH:mm` です。コード・式の実行は行いません。

通知済みのIDと対象日だけを `history.json` に保存します。通知名・メッセージを通知履歴へ複製せず、外部送信もしません。同じIDの通知を表示後に同日内で時刻・文言を編集しても再通知しません。削除済みIDの履歴は次回の履歴保存時に整理します。利用者の通知JSON・バックアップ・一時ファイルは配布ZIPから除外します。

実際のWindowsの日時・スリープ復帰・通知領域との動作は、[Windows確認手順](WINDOWS_CHECKLIST.md)を参照してください。LinuxのQt offscreenと合成日時による検証です。

## 営業日を使う通知（v0.16.0）

「月末の最終営業日」「毎月○日までの最終営業日」を追加しました。条件IDは `month_end_business_day` と `monthly_business_day_before`（`day` を指定）。トレイまたは設定の「休日・対象ファイル・話題の表示」で、日本の祝日・営業曜日・会社休日・特別営業日を変更できます。特別営業日は他の休日指定より優先します。従来の「平日」は引き続き月〜金です。

日本の祝日は2000〜2099年の現行ルールに基づくオフライン計算で、2019年の即位関連・2020/2021年の移動も含みます。将来の法改正や臨時休日は会社休日で補ってください。暦と登録通知は外部送信しません。営業日設定が読めない場合は営業日通知を止め、設定画面に説明を出します。


吹き出しの「通知を設定する」で作る[単発通知](ONE_SHOT_NOTIFICATIONS.md)は、この繰り返しルールの編集とは別です。
