# 成長システム基盤 v0.30.0

導入前の保存地点は `yohaku-v0.29.0-before-growth`、コミット `ab103aefbd4d6154dd58d4ad4f1bdf630e8ab423` です。実験前のDataも別途保管してください。成長システム導入後のDataを旧版へ上書きして戻す操作は行いません。

## 使い方

タスクトレイを右クリックし「一緒に過ごした記録・衣装」を開きます。キャラごとのレベル、EXP、一緒に過ごした時間、トロフィー、解放済み衣装を確認できます。実用機能のレベル制限はありません。性格設定は変更しません。

「衣装」で頭・体・アクセサリーの各枠を選びます。取得した衣装は自動装着しません。「装着しない」で解除できます。キャラ切替時はそれぞれの成長・装備を復元します。秘密の未達成トロフィーは？？？、無効化・削除したパックで取得したトロフィーはIDと取得日時を表示します。

## 編集ツールとコンテンツの追加

同じ配布フォルダの **YohakuContentEditor.exe** を起動します。常駐アプリとは独立したプロセス・ウィンドウです。常駐アプリの成長画面からも起動できます。ソースの場合は `python content_editor_main.py` です。互換起動方法は `Yohaku.exe --content-editor`、任意のコンテンツ保存先は `--content-root <フォルダ>` です。

1. 「新しいパック」で英小文字などの固定IDを入力します。IDは後から取得記録に使うため変更しません。
2. 種類を選び、追加・複製・削除します。セリフ・演出・トロフィー・衣装・レベル報酬に対応します。
3. 条件は追加・編集ボタンからフォーム入力します。複数条件はすべて満たすANDです。文章は7性格と共通を切り替えて編集できます。空欄の性格は共通を使い、共通も空欄ならその性格では発生しません。
4. 衣装画像を選ぶとパック内imagesへコピーします。キャラ・フレーム・X/Y・倍率・描画順を指定し、プレビューで確認できます。
5. 「検証」「保存」を行い、Yohakuの成長画面で「パックを再読み込み」を押します。EXPや取得履歴は初期化しません。

パックを取り込む場合は「パックを取り込む」からpack.jsonを選びます。JSONと参照するPNGだけをコピーし、Pythonなどは実行・取り込みしません。重複IDは取り込めません。既存パックの有効・無効はエディタのチェックで変更します。自動ホットリロードは行いません。

編集はメモリ上に保持し「保存」で書き込みます。パックを切り替える／閉じるとき未保存なら破棄を確認します。画像選択時にコピーした未使用画像は残る場合があります。他エディタによる更新を検出した場合は上書きせず停止します。再度開き直して編集してください。不正な既存パックは問題を表示し、エディタでは開きません。

## 初期サンプルと設定可能な仮値

- 1時間で60 EXP。Lv.2は累計60 EXP。Lv.nの必要累計は初期値 `30*(n-1)*n`、最大Lv.100です。baseの全体設定でレベルごとの累計値を編集できます。既に取得したレベル・解放物は数値変更で取り消しません。
- 抽選機会は60秒ごと。追加セリフ1件（5%、2時間間隔、1日2回）、小さなきらめき1件（1%、6時間間隔、1日1回、2 EXP）を同梱します。レベルで確率を自動増加させません。各機会で最大1件です。
- 累計1時間のトロフィー1件（5 EXP）、Lv.2のリボン1件、レベル報酬1件。大量の衣装・台詞を含む完成コンテンツ集ではありません。
- 連続日数は暦日が初期値。営業日方式へ変更すると既存の会社カレンダー（日本の祝日・ユーザー休日・営業日）を参照します。過去370日までを保持します。
- 操作の継続はアイドル60秒未満を初期値とする推定値です。許容秒数は編集可能です。連続時間は再起動・ロック・スリープ・不明計測で切ります。
- XPという表記は使用せず、画面は **EXP**、JSONキーは `exp` / `exp_per_hour` / `exp_interval_seconds` を使用します。添付原本の仕様書には旧表記が残っています。

## 計時と通知

内部では5秒間隔で、WindowsのQueryUnbiasedInterruptTimeによるスリープを除いた実経過時間を記録します。20秒を超える処理停止、壁時計との大幅な差、時計の巻き戻しは補完しません。初期値ではWindowsロック中も除外し、全体設定でロック中の加算だけ変更できます。アイドル中、キャラ非表示中も起動していればEXPを加算します。隠す操作だけで成長は止まりません。

EXPは5分ごとにまとめて獲得し、その時点でJSONを保存します。初期値は5分で5 EXPです。通常終了時は未獲得の端数秒数も保存し、次回へ引き継ぎます。起動日変更・実績や演出の報酬・装着変更時も記録を保存します。異常終了時に未保存の最大約5分が失われる場合があります。終了していた期間は加算しません。同じDataでは既存の多重起動ロックが重複加算を防ぎます。別のDataを使う別コピーは独立したアプリとして扱います。

レベル・実績は通常の吹き出し（60秒）で知らせます。追加セリフ・演出は20秒です。予定・新着メール・既存通知を先に扱い、フォーム入力中、他の吹き出し、設定画面、画面共有／非表示、休止、静かな時間帯、会議抑制中には割り込みません。成長通知は最大20件の待ち行列で、キャラ変更・再起動により未表示通知が省略されることがあります。取得済み記録は画面に残ります。音声は出しません。

## 条件タイプ

| タイプ | 内容・取得根拠 |
|---|---|
| metric | 既存の会話用PC状態集計（CPU・メモリ・操作・予定など）から比較 |
| continuous_input | この起動中に操作が続いた推定時間（分） |
| app_count | 表示中のトップレベルウィンドウを持つ実行ファイルの種類数。同一EXEの複数ウィンドウは1、ツール・シェル・バックグラウンドのみのプロセスは除外 |
| streak_days | キャラ別の連続起動日数（暦日／営業日） |
| total_minutes | キャラ別の累計起動時間（分） |
| time_range | 時刻の範囲。日をまたぐ指定にも対応 |
| date_range | 日付の範囲（YYYY-MM-DD） |
| day_kind | 会社カレンダーの営業日／休日 |
| outside_hours | 設定済み08:30〜17:30等の所定時間外にPC操作があった推定 |
| event_count | 指定した演出IDの遭遇累計 |

PC状態の集計オフ時は操作・アプリ数を新たに取得しません。会社カレンダーが不正な場合は営業日・休日・所定時間外・営業日方式の連続起動の条件を満たさないものとし、初期値で代用しません。既存の取得設定や許可に従い、不明な値は条件を満たさないものとします。実行ファイルのパス・タイトル・入力文字はこの機能のためには保存せず、アプリ数の集計値のみを使用します。権限で確認できないアプリがある場合は数を不明として扱います。

PC利用だけで休日出勤・残業の勤務事実を断定しません。勤怠連携や手動勤務登録、ランキング、連続作業を促す機能は実装していません。トロフィーは初回日時と付与EXPを一度だけ記録します。「最高値」は最初の数値条件の観測最大値です。

## JSONと画像

- `Data/growth.json`：schema_version=1。charactersのA/B/Eごとにexp、exp_seconds（次回EXP付与までの端数秒）、level、seconds、days、trophies、best、unlocked、equipped、events、sequenceを保存します。
- `Data/growth.json.bak`：直前の完全な保存データ。
- `Data/content/<パックID>/pack.json`：schema_version=1。id、name、enabled、lines/events/trophies/costumes/rewards。baseのみconfigを持ちます。
- 項目IDは `pack_id:item_id` で参照します。表示名を変えても取得履歴は保持します。パックを無効・削除しても記録は残し、再追加した同じIDの実績EXPは再付与しません。
- `Data/growth-content.log`：今回のパック読み込み問題を最大200件まで記録します。際限なく追記しません。

サンプルbaseは初回だけ組み込み素材からコピーします。以後ユーザー編集版を上書きしません。新しいパックはData/content直下へ配置します。構文・型・ID重複・参照・画像を検証し、不正な項目と依存する項目を除外します。有効なbaseが読めない場合は成長を停止しますが、予定や履歴など既存機能は続行します。進行JSONが不正な場合はバックアップを表示用に読み、元ファイルは上書きせず成長を停止します。終了後に原本を別途退避し、有効なバックアップからgrowth.jsonを復元して再起動してください。

保存は同じフォルダの一意な一時ファイルから置換します。EXP・実績・装備は同じトランザクションで保存し、成功後に表示します。コンテンツ保存は別ファイルで、進行を更新しません。今後の新しい条件タイプや再生方式には本体の改修が必要です。スクリプトのevalや任意コマンドはありません。

衣装画像は透過PNGをパック内の相対パスで指定し、各画像8MB・2048px四方までです。キャラの既存切り抜き後キャンバスを座標基準として、背面→本体→前面→アクセサリーの順に重ねます。各variantでcharacter、frames（0〜27）、image、x/y、scaleを指定します。16〜23は歩行、24〜27は正面です。左右反転・拡縮は衣装を合成した本体と一緒に行います。移動アニメの中間描画にも適用します。未知・未対応フレーム、手紙／予定表／メモ／預かり／つまみ姿は非表示にし、不適切な別フレームの差分を流用しません。
