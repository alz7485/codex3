# v0.19.1 修正内容と検証範囲

v0.19.0候補の通常監査で確認した7件と、吹き出し内の単発通知の日時入力を修正しました。12話題・252文の追加も含みます。全76話題・7性格それぞれ217文、計1,519文です。

## 単発通知の日時入力

- 旧時刻欄では、全選択して17:30と打っても元の時が残り、分だけ変わる症状を再現しました。時刻を `HH:mm` 全体で入力・貼り付けできる欄へ変更しました。09:05、17:30、00:00、23:59を実際のキー入力で確認しています。
- 入力途中・不正な時刻・今日の現在以前の時刻ではOKを無効にします。編集中の文字を勝手に確定したり、別の時刻に置き換えたりしません。
- 今日なら次の分以降、明日以降なら00:00から指定できます。カレンダーと日付欄の双方で過去日を選べません。
- 入力中も日時の下限を更新し、保存直前にも再確認します。時刻を過ぎても本文は保持します。
- 23:59に新規入力する場合は翌日00:00から。入力中に選べる日付が変わった場合は、日付か時刻を選び直すまでOKを無効にし、意図せず翌日の通知として登録することを防ぎます。

## 監査指摘の対応

| ID | 修正 | 回帰確認 |
|---|---|---|
| C-001 | 予定の採用と最終マージを対象期間との交差で判定。前日開始の進行中・当日終了済みの予定を保持 | 予定表／未承諾案内の両経路、深夜境界、Controller→Engineで残り1件・30分となり「全て終了」を発話しない |
| C-002 | 整数の有限性判定でfloatへ変換しない。範囲外は通常の入力エラーへ | 新割合3欄と従来の数値条件に巨大整数を設定し、例外を漏らさず初期値へ退避。元ファイル不変 |
| C-003 | 移行前にルール配列の最低限の構造を検査 | 旧形式の整数ルール要素を拒否し、元ファイル保持で退避 |
| C-004 | 非AND/OR条件の余剰conditionsを拒否。実行時の子走査もAND/ORに限定 | 不正なJSONの保存拒否・保存済み原本不変、非複合条件のメタデータを子として実行しない |
| C-005 | 新話題追加で2MiBを超えるときは追加を見送り、既存文書を利用。移行印も収まらなければ元の文書を維持 | 上限付近の有効64話題JSONで文章・条件・無効化・optionsを保持し、保存・再読込・バックアップも確認 |
| C-006 | 条件切替に合わせて割合上下限のアクセシビリティ名・単位説明を更新 | 実Qt APIで割合と通常集計の名称を往復確認 |
| C-007 | 条件一覧を現行15種に更新 | 実KINDSの全種類を表に照合 |

容量境界の確認では、JSONの整形によって保存後のファイルが読込上限を超える経路も修正しました。保存と書き出しは、整形しても収まるときは読みやすい形式、収まらないときは通常のJSON形式とし、改行変換による増加を避けてUTF-8/LFで出力します。制限そのものを緩めたり、利用者のセリフを削ったりはしません。
