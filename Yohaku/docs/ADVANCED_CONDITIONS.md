# 追加の会話条件と表示設定 — v0.16.0

ディスク空き容量を除く7案を実装しました。通常会話は初期約10分ごと、本文だけの白い吹き出しです。条件が成立しても必ずその場で発言する仕組みではありません。通知・会議中・非表示・静かな時間等の既存の優先順位と抑制を維持します。

| 追加 | 初期値・操作 |
|---|---|
| 状態の継続 | CPUの約1分平均が80%以上で3分、メモリ85%以上で5分。値と継続分数は会話編集UIで変更できます |
| 状態からの復帰 | CPU高負荷3分のあと50%以下、メモリ高使用率5分のあと70%以下。途中の中間値を通っても回復を判定します。30分以上の操作なしを確認したあと、操作なし時間が1分未満になった場合も候補になります |
| 会議の詰まり具合 | 今日の会議合計240分以上、現在または次の予定から3件以上連続、2件以上の会議が続き次の休憩が9分以下。連続とみなす会議間隔は初期10分で変更可能 |
| 指定ファイル・フォルダー | 対象を登録して、今日の履歴にある／ない／記録回数の範囲を選びます。初期の2話題は無効で、対象選択と有効化が必要です |
| 祝日・会社休日 | 日本の祝日、営業曜日、会社休日、特別営業日。通常会話の営業日・休日条件、勤務時間の初期話題、営業日限定の退勤前通知、登録通知の最終営業日で使います |
| バッテリー・電源 | 初期は残量20%以下かつAC未接続で候補にします。ACの未接続→接続も候補。起動時に接続済みなだけでは発言しません |
| 話題の一時停止 | トレイ右クリック→「直前の話題」→今日は休む／減らす／戻す。設定画面から任意の通常会話も調整できます |

## 設定する場所

トレイ右クリック、または「キャラと通知」の「休日・対象ファイル・話題の表示」を開きます。

- **営業日・休日**：祝日利用のオン／オフ、営業曜日、会社休日、特別営業日。日付はYYYY-MM-DDを1行に1件。特別営業日を最優先します。
- **対象ファイル**：ファイル／フォルダーを選び、管理用の名前を付けます。最大30件。既存のファイル履歴を照合し、フォルダー配下の保存先に一致する記録を合計します。対象を読む・開く・走査する処理はありません。
- **会議**：何分以内の間隔を連続会議とするか変更します。
- **話題の表示**：今日は休む／減らす／戻す。このタブだけは操作時にすぐ保存します。他の3タブは「保存して反映」で適用します。

初期の会社休日・特別営業日・対象ファイルは空です。プレビュー画像の日付と保存先は合成の例です。

継続時間・変化前後の範囲・発生後に話せる期間・対象の記録条件・営業日／休日は、通常の会話編集画面の「発生ルール」で変更します。AND／ORにも組み込めます。各話題の文章・表情・重み・同じ話題の間隔も変更できます。

「今日は休む」は再起動後も当日の間は継続し、翌日に解除します。「減らす」は通常の同じ話題の間隔を2倍（最短2分）にし、手動クリックでもその間隔を守ります。元の会話JSONの有効状態や間隔は書き換えず、表示設定を戻すと元に戻ります。

## 条件JSON

| kind | 項目 |
|---|---|
| `metric_sustained` | `metric`, `minimum`, `maximum`, `duration_minutes` |
| `metric_transition` | 変化前の`metric`, `minimum`, `maximum`、変化後の`to_minimum`, `to_maximum`、変化前の継続`duration_minutes`、発言期間`window_minutes`。前後の範囲は重ねません |
| `idle_return` | `idle_minutes`, `window_minutes` |
| `watched_file` | `target_id`、`state`は`opened_today`／`not_opened_today`／`count_range`、`minimum`, `maximum` |
| `business_day` | `expected: true`なら営業日、`false`なら休日 |

継続は0〜1440分、発言期間は1〜60分です。復帰の発言期間は初期10分で、その間の会話候補として同じ発生を1回だけ使います。期間を過ぎれば後追いしません。取得不能・不明値や15秒を超える判定の空白では、継続・復帰の状態を作り直します。再起動時も最初から確認します。

追加集計値は`battery_percent`、`ac_connected`、`battery_charging`、`daily_meeting_minutes`、`consecutive_meetings`、`next_meeting_gap_minutes`です。AC接続・充電中は1がはい、0がいいえ。充電開始は`battery_charging`の0→1の変化条件でも設定できます。対象の文章には`{target_name}`と`{target_open_count}`も使えます。

## 取得範囲と制限

CPU・メモリ・電源はPC状態集計オン時だけです。バッテリーのないPCや取得不能時は、バッテリーの条件を成立させません。値・電源状態・継続や復帰の観測はファイルに保存しません。

会議時間は当日の取得済み予定の開始〜終了の重複を除いて合計します。連続件数は重複予定も含み、現在進行中または次に始まる会議のまとまりの件数です。同じまとまりに含まれる終了済みの会議も数えるので、会議間の短い休憩中にも判定できます。休憩は現在の会議終了と現在時刻の遅い方から、次の会議開始までです。予定の一部取得・切断・古い取得値では判定しません。

対象ファイルは履歴記録オン時だけ判定し、オフ・保存失敗・取得不能では未使用とみなしません。「記録にない」はアプリ起動前や検出漏れを含むため、実際に開いていないことや業務の未完了を断定しません。履歴の3か月・15,000件の保持範囲も変えません。

日本の祝日は2000〜2099年の現行ルールでオフライン計算します。振替休日・国民の休日、2019年の即位関連、2020/2021年の移動を含みます。将来の法改正・臨時休日は会社休日で補ってください。従来の「平日（月〜金）」は残し、祝日等を考慮する登録通知には「最終営業日」を選びます。

## 保存と配布

休日・対象・会議間隔は`%LOCALAPPDATA%\Yohaku\context_options.json`、話題の表示設定は`topic_preferences.json`に保存します。各JSONは保存成功後だけ反映し、バックアップを残します。これらとバックアップ・一時ファイルは配布ZIPに含めません。営業日設定が壊れた場合は営業日通知等を停止し、話題の表示設定が壊れた場合は通常会話を控えて画面にエラーを示します。元ファイルは保持します。

旧会話JSONには新しい10話題を一度追加し、独自の文章や条件を保ちます。初期状態のCPU・メモリ高使用率だけ継続条件へ移し、初期の勤務時間の話題を営業日に合わせます。追加後に削除した話題は再追加しません。ルール上限200件を超える追加はしません。

Linux / Qt offscreen・合成データ・模擬APIで検証します。Windows実機、バッテリーやスリープ、実Office・Outlookでの確認は別途必要です。

## 吹き出しから履歴・予定を使う

「ファイル起動履歴を見る」は、今日の新しい順に保存先の重複をまとめた直近50ファイルを縦のリンクで表示します。ファイル名を1回クリックすると既定アプリで開き、吹き出しは残ります。同名でも保存先が違えば別リンクで、ポインターを置くと保存先を確認できます。末尾の「管理画面を開く」を押すと吹き出しを閉じ、従来の履歴画面を開きます。過去3か月・15,000件、全履歴検索、日付選択、ダブルクリックは維持します。

予定の吹き出しには「Outlookの予定を開く」を付けました。明示クリックで従来版Outlookの予定表へ移動し、未起動なら起動を試みます。予定の読取監視は従来どおりOutlookを自動起動しません。予定・メールの追加、保存、承諾、返信、既読化は行いません。画面移動は別スレッドで行い、失敗は吹き出し内で説明します。
