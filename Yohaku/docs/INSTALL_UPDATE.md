# Yohakuの導入・更新・困ったとき

## 初めて使う

1. 同じ版のonedirビルド用ZIPを1つ取得し、新しい空のフォルダーへ展開します。testsの追加や旧分割版との統合は不要です。
2. Windowsに64bit Python 3.11または3.12を用意します。バッチが使えない場合は `ONEDIR_COMMAND.txt` の5行を順に入力します。
3. ビルド前に収録ファイルを自動検査します。不足・不一致が出た場合は、同じ版のビルド用ZIPを空の場所へ展開し直します。
4. 出力されたonedirはフォルダー全体で使います。`Yohaku.exe` と `_internal` を分離しないでください。ビルド済みonedirを受け取ったPCにはPythonの導入は不要です。
5. `Yohaku.exe` を起動します。従来版Outlookとの接続とファイル履歴の記録は、設定から必要な場合にオンにします。最初はOutlook未接続・ファイル履歴オフです。

会社のPCへの導入・Outlook連携は、社内の利用ルールに従ってください。新しいOutlookは連携対象外です。

## 毎日の操作

- キャラの左クリックで一言、右クリックで予定・ファイル履歴・設定・単発通知・非表示の5択を出します。ドラッグで移動できます。
- 通常メッセージは20秒、通知は1分。本文クリックで閉じます。通知の入力中と、困る・怒る反応は自動で閉じません。
- タスクトレイのアイコンを左クリックすると表示・非表示を切り替えられます。終了はトレイの右クリックメニューから行います。
- 通常メッセージ中は歩きます。選択肢や通知入力、設定・履歴画面の操作中は止まります。歩行・アニメーション・静かな時間は設定できます。
- 単発通知は日付・HH:mm・内容を入力します。過去日と今日の過去時刻は登録できません。非表示やアプリ停止中に期限を過ぎた通知は、表示できるタイミングで知らせます。

## 更新する

1. 起動中のYohakuをトレイから終了します。
2. 現在のYohaku.exeの隣にある `Data` フォルダー全体をバックアップします。この中には個人の設定・登録通知・記録オンの場合のファイル履歴が含まれます。
3. 新しい版は、古い実行フォルダーへ重ねず、空の別フォルダーへ展開・ビルドします。onedirでも新しいフォルダー全体を配置します。
4. 使用中の `Data` を、新しい `Yohaku.exe` の隣へコピーしてから起動します。設定・会話JSON・通知・履歴を引き継ぎます。
5. キャラ・表示位置・履歴記録のオン/オフ・登録した通知が引き継がれていることを確認します。

v0.28.2以前の保存先は `%LOCALAPPDATA%\Yohaku` です。v0.29.0以降は、Dataがない初回に旧保存先からコピーします。既存のDataは空フォルダも含めて優先し、元の保存先を削除しません。[保存先と移行の詳細](PORTABLE_DATA.md)

会話JSONを保存すると直前の内容は `Data\dialogue.json.bak` に残ります。今後の更新ではDataを持ち越してください。古い版への差し戻しは、その版が新しい設定形式に対応しているとは限らないため、更新前のバックアップも保管してください。

## 困ったとき

| 状態 | 確認・対応 |
|---|---|
| キャラが見えない | トレイを左クリック。画面共有モード・非表示・静かな時間・歩行オフも確認します。二重起動の案内が出た場合は既存のトレイを確認します |
| ビルドで不足・不一致が出る | 同じ版のZIPを両方、空の場所へ展開します。使用中の設定ファイルは削除しません |
| メール・予定を取得できない | 従来版Outlookを起動し、Yohakuの設定で接続状態を確認します。社内のCOM制限やOutlookの状態も確認します |
| 履歴が出ない | 記録オン以降に開いたファイルだけを記録します。オフだった期間は後から復元しません。保持は3か月・最大15,000件です |
| 通知が遅れる | アプリの終了・非表示・画面共有・静かな時間・一時停止・入力中では保留します。PC停止中そのものの時刻には通知できません |
| 保存エラーが出る | 入力は保持します。保存先の権限・空き容量を確認して再試行します。使っているJSON・履歴DBを削除して解決しようとせず、まずバックアップします |
| 会話JSONを読めない | 元ファイルは保持します。正常なバックアップや編集画面で書き出したJSONから復旧します。`dialogue.json.bak` を使う場合も、終了後に現在のファイルを別名で保管してから差し替えます |

## 確認用コマンド

ソースを統合したフォルダーでは、次のコマンドで不足・異版混在だけを確認できます。

```powershell
.\.venv\Scripts\python.exe scripts\check_source.py
```

ビルドしたEXEの素材・3体の描画・吹き出しを確認する場合は、次を実行します。通常のアプリは起動せず、設定・履歴・Outlookに触れません。指定したJSONに結果だけを出します。

```powershell
.\dist\Yohaku\Yohaku.exe --self-check smoke-report.json
```

ソースを開発用に変更した場合は、`scripts/package_source.py` でマニフェストと配布ZIPを作り直してからビルドします。通常の会話編集や設定変更は、配布ソースの書き換えを必要としません。
