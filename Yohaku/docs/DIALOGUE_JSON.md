# 会話JSONの編集と復旧

通常は「キャラと通知」→「会話文・発生ルールを編集」を使用します。通知領域のアイコンを右クリック→「会話を編集」でも開けます。

初期データは `companion/assets/dialogue/default_dialogue.json` です。Pythonコード内に会話文や個々の発生ルールは保持せず、このJSONを同じ評価処理で読み込みます。onedirにも同梱します。

編集画面の「保存して反映」で `%LOCALAPPDATA%\Yohaku\dialogue.json` へUTF-8で保存します。動作中の会話・表示秒数・キャラ説明へすぐ反映します。初回保存前は初期データを使い、旧版で選んだ会話間隔を引き継ぎます。以降、会話間隔の正本はこのJSONです。「キャラと通知」の間隔変更も同じJSONへ保存します。

## 編集画面

- **会話文**：性格→話題→セリフを選んで本文を編集します。改行を含められます。追加・削除はこの性格・話題のセリフにだけ適用します。1話題1〜200件、1件1〜1000文字です。
- **発生ルール**：有効・無効、話題名、条件、表情、出現しやすさ、同じ話題の間隔を指定します。「話題を追加」で新しい自動会話を作れます。新しい話題には7種の性格のセリフ欄を用意します。呼びかけ・操作時の案内・予定通知は専用の発生方法に対応し、削除はできません。無効化はできます。
- **全体設定・性格**：会話間隔、表示秒数、予定通知の何分前、会議中の抑制、連続・重複回避、抽選方式、4キャラの基本の性格・説明・代表的な一言を編集します。
- **保存して反映**：全項目を検証して保存します。保存前の編集は現在の動作に影響しません。
- **変更を取り消す**：最後に保存した内容へ戻します。
- **初期値へ戻す**：編集中の内容を初期値へ戻します。保存ボタンを押すまでは動作を変更しません。
- **JSONを読み込む／書き出す**：編集内容をほかのPCへ移せます。読み込み後も保存ボタンで確定します。書き出しは動作中の会話へ反映する操作とは別です。

保存に失敗したときは動作中のデータ・元のJSONを保持し、編集内容も残します。閉じる／終了時に未保存の内容があれば、保存・破棄・キャンセルを選べます。呼び出しの「非表示にする」や画面共有は編集画面を隠しますが、編集中の内容は保持します。

## JSONの形式

`schema_version` は `2`。次の5項目を持つオブジェクトです。

| キー | 内容 |
|---|---|
| `schema_version` | 形式の版。整数2。旧版1は編集内容を残して移行 |
| `profiles` | A/B/E/Fそれぞれの `voice`（基本の性格）、`description`、`tagline` |
| `phrases` | 性格名 → 話題ID → セリフ文字列の配列。すべての話題を7種の性格に用意 |
| `rules` | 発生ルールの配列。IDは小文字英数字と_、最大40文字、重複不可 |
| `options` | 会話と表示の全体設定 |

性格の識別名は既存設定を引き継ぐため「控えめな皮肉屋」「冷静な案内役」「元気な応援係」「のんびりした同僚」「馴れ馴れしい関西弁」「寡黙な先輩」「孤高の債務者」の7つです。各性格の本文や、キャラとの対応・説明は編集できます。

全体設定：

| 設定 | 範囲・値 |
|---|---|
| `interval_minutes` | 自動会話の間隔。1〜1,440分。初期10 |
| `bubble_seconds` | 通常メッセージ・呼び出し・予定/履歴の照会の表示。5〜300秒。初期20。通知は別に60秒固定 |
| `meeting_lead_minutes` | 予定を何分前から知らせるか。1〜120分。初期10 |
| `suppress_during_meetings` | 会議中の自動雑談を抑制。true/false |
| `repeat_window` | 同じ話題内で避ける直近セリフ数。0〜64。初期12 |
| `avoid_consecutive_topic` | 同じ話題の連続を避ける。true/false。他に候補がない場合は再発言間隔を満たす候補を使用 |
| `work_start` / `work_end` | 始業・終業のHH:mm。初期08:30 / 17:30。始業は終業より前 |
| `active_threshold_seconds` | 最終操作から何秒以内を操作ありと数えるか。5〜600秒。初期60 |
| `selection_policy` | `least_recent`（未使用・久しぶりを優先）／`weighted`（重みで抽選） |

発生ルール1件の例（JSON全体ではなく `rules` の要素）：

```json
{
  "id": "custom_1",
  "label": "水曜日のひとこと",
  "enabled": true,
  "trigger": "auto",
  "condition": {"kind": "weekday", "days": [2]},
  "expression": "wink",
  "weight": 3,
  "cooldown_minutes": 60
}
```

例の条件は水曜日です。複数条件は `all` / `any` の `conditions` 配列で組み合わせられます。話題名は表示用で、条件を決めるのは `condition` です。

`trigger` は、`call` では `click`、`meeting` では `reminder`、操作時の案内では `action`、新着通知では `notification`、その他の話題では `auto` です。編集画面が自動で指定します。

`condition.kind` は次の15種です。

| 種類 | 条件の項目 |
|---|---|
| `metric_range` | `metric` と `minimum` / `maximum`。上限null可。不明値は候補にしない |
| `all` / `any` | `conditions` 配列に1〜8件。最大4階層。すべて／いずれかを満たす条件。`conditions` はこの2種類だけで指定可 |
| `always` | 常時候補 |
| `time_range` | `start` / `end` を `HH:mm` で指定。開始を含み終了を含まない。日跨ぎ対応。同時刻なら終日 |
| `weekday` | `days` に月曜0〜日曜6。1つ以上 |
| `session_range` | `minimum_minutes` / `maximum_minutes`、`first_only`。上限null可。起動からの経過であり、実際の作業時間ではない |
| `before_meeting` | `minimum_minutes` 超〜 `maximum_minutes` 以内に開始する予定。接続済みで最新の予定データを使えるときだけ |
| `after_meeting` | 終了時刻から `minimum_minutes` 以上〜 `maximum_minutes` 以内の予定。同じく接続が必要 |
| `metric_ratio` | `numerator` / `denominator` / `minimum_total` / `minimum` / `maximum`。最低計測量を満たすときだけ割合（%）を判定。詳細は[割合条件](EXTENDED_LOGIC.md) |
| `metric_sustained` | `metric` / `minimum` / `maximum` / `duration_minutes`。範囲内の状態が指定分続く |
| `metric_transition` | `metric` と変化前 `minimum` / `maximum`、変化後 `to_minimum` / `to_maximum`、`duration_minutes` / `window_minutes` |
| `idle_return` | `idle_minutes` 以上の操作なしから戻り、`window_minutes` 以内 |
| `watched_file` | `target_id` / `state` / `minimum` / `maximum`。登録した対象の履歴を判定 |
| `business_day` | `expected` がtrueなら営業日、falseなら休日。会社休日の設定に従う |

`weight` は1〜100。同じ優先度の候補内での出現しやすさです。`cooldown_minutes` は0〜1,440分。自動会話はこの間隔を守ります。手動でキャラを続けて左クリックしたときは間隔を緩めて応答します。候補をすべて無効にした場合、手動操作には編集画面での確認を案内し、自動会話は出しません。初回限定の起動後挨拶は、該当する場合に優先します。

表情は `neutral` / `blink` / `happy` / `notice` / `think` / `sleepy` / `proud` / `concern` / `wink` / `laugh` / `curious` / `relaxed` / `nod` / `talk` / `greet` / `stretch`  / `front` / `front_blink` / `troubled` / `angry` の20種です。

JSONからコードや数式を実行する機能はありません。入力内容や文書本文は会話の条件に使いません。操作の有無・時間・件数・PC全体のCPUとメモリ使用率と、オンにしたファイル履歴の開き直し回数を使用します。静かな時間・おやすみ・非表示中の停止は従来の設定に従います。

## 復旧と直接編集

- 既存JSONを保存する際、直前の内容を同じフォルダーの `dialogue.json.bak` にコピーします。
- 起動時にJSONが不正なら、元のファイルを上書きせず初期値で動作し、編集画面に理由を表示します。
- バックアップは「JSONを読み込む」で選び、「保存して反映」で復旧できます。`.json.bak` もファイル選択で直接指定できます。
- 外部エディタで直接編集した場合は、編集画面で読み込んで保存するか、アプリを再起動して反映します。ファイルの自動監視は行いません。
- JSON全体は2MB、話題は最大200件です。空のセリフ、ID重複、不明な条件、範囲外の数値は保存・読み込み時に拒否します。
- ソース配布ZIPには初期JSONを含め、利用者の `dialogue.json` とバックアップは含めません。

旧版1のJSONは既存のセリフ・設定を残し、新しい条件と受信通知、勤務時間の初期値を追加して版2へ移行します。元ファイルは保存ボタンを押すまで書き換えません。集計値一覧と差し込み文字列は [CONTEXT_NOTIFICATIONS.md](CONTEXT_NOTIFICATIONS.md) を参照してください。

`content_revision: 3` は未読会話を追加した初期文言の版です。schema_versionは2のままです。旧JSONは他の編集内容を保持し、未読話題を一度だけ追加します。旧受信セリフに `{mail_count}` があれば件数なしの文言へ移行します。更新後に未読話題を削除した場合は再追加しません。

通常会話の `priority` は任意の0〜5（省略時0）。未発言・最も古い話題を優先する方式で、再発言間隔を満たす話題に追加の抽選枠を与えます。初期の未読話題は `weight: 2, priority: 1, cooldown_minutes: 60`、条件は `metric_range` の `unread_mail_count` が5以上です。受信通知と違い、自動会話の間隔・抑制を守ります。値が不明なら発言しません。

`{hours_to_end}` は「1時間40分」「40分」「2時間」のような文字列です。小数の時間数を使いません。既存の `{hours_to_end}時間` という文言も互換処理で単位の重複を避けます。


## 連打への反応

`click_reactions_version: 1` を追加しました。旧JSONには新しいオプションと `click_concern` / `click_angry` の操作用ルール・セリフを一度だけ追加します。既存の文言・設定は保持し、読み込みだけでは元ファイルを書き換えません。

| optionsのキー | 初期値と範囲 |
|---|---|
| `click_reactions` | true。連打への反応のオン・オフ |
| `click_window_seconds` | 5。直近のクリックを数える秒数、1〜30秒 |
| `click_concern_count` | 4。困る段階の回数、2〜30回 |
| `click_angry_count` | 7。怒る段階の回数、3〜60回。困る回数より多い値 |
| `click_recovery_seconds` | 10。最後の受け付けたクリックから次回判定でリセットするまで、1〜120秒。判定期間以上 |

上記はすべて「全体設定・性格」から編集できます。2つのルールは `trigger: action`、条件は `always`。セリフ・表情・有効無効は他の話題と同じ編集UIを使用します。自動会話の抽選には入りません。連打判定はキャラ上でドラッグせずに完了した左クリックだけを数え、現在の段階は次のクリックまでの休止がリセット秒数に達するまで維持します。単調増加時計を使い、回数や時刻はディスクへ保存しません。

連打の反応は本文をクリックして閉じるまで保持します。`bubble_seconds` や `click_recovery_seconds` に達しても自動消去しません。その間はキャラの左クリックを数えず、セリフの抽選もしません。右クリックの呼び出しは使用でき、呼び出しの本文クリックやEscの明示的な終了でも再開します。通常の会話・通知の表示秒数には影響しません。

`click_repeat_seconds` を追加しました。初期30、1〜600秒。同じ段階の反応の再発言を抑え、短い連打の回数リセットではこの間隔を消しません。困る段階と怒る段階は別に判定します。編集UIの全体設定から変更できます。

`anonymous_mail_version: 1` は送信者名を出さない文言への移行済みを表します。旧JSONの受信通知カテゴリだけを「メールが届きました。」「新しいメールが届きました。」へ一度更新し、それ以外のセリフ・性格・条件・間隔を保持します。元ファイルは保存まで書き換えません。以後の受信セリフの編集は保持します。`{mail_from}` は使用せず、旧呼び出しから値が渡っても空文字にします。送信者情報は取得しません。

プリセットは全体設定の `interval_minutes` と通常設定の会話・歩行・アニメーションのオンオフだけをまとめて変更します。未保存の会話編集は破棄せず、開いている編集内容はそのまま残します。

`naming_version: 1` は正式名称への移行済みの印です。旧初期セリフの自己紹介と完全一致する文言だけを置き換え、独自のセリフ・条件・性格設定は保持します。移行後に利用者が編集した文言は再置換しません。内部のキャラ識別子A/B/E/Fは引き継ぎ、表示名はつづり・ビット・ペギー・きなこです。

## CPU・メモリの会話条件

`metric_range` の `metric` に `cpu_percent`（直近約1分の平均）と `memory_percent`（PC全体の物理メモリ）を使えます。取得値は0〜100%、不明値では条件が成立しません。初期値はCPU高80〜100／低0〜20、メモリ高85〜100／低0〜50です。本文には `{cpu_percent}`・`{memory_percent}` を差し込めます。高使用率の話題は60分、低使用率は120分空ける通常会話です。

`resource_context_version: 1` は追加済みの印です。旧JSONには4話題と各性格分の文章を読み込み時に一度追加し、元ファイルは保存操作まで変更しません。既存の文章・条件と追加後の削除を維持します。既に200件のルールがある場合は上限を超えて追加せず、既存ルールを保ちます。保存後はこの印もJSONに保持されます。

追加した条件とJSONの各項目は[ADVANCED_CONDITIONS.md](ADVANCED_CONDITIONS.md)を参照してください。`advanced_context_version: 1` は追加済みの印で、既存の独自セリフ・条件を保ち、追加後に削除した話題は再追加しません。初期状態のCPU・メモリ高使用率の条件だけは継続3分／5分へ移行し、初期の勤務時間の話題には営業日を使います。編集済みの異なる条件は維持します。


## 追加の性格（v0.18.0）

`personality_expansion_version: 1` で7性格への追加を管理します。[性格の説明](PERSONALITIES.md)を参照してください。旧4性格・条件・キャラ設定は保持し、既存の話題IDに合わせて新3性格を追加します。独自の話題には「控えめな皮肉屋」の文章を新性格の編集用初期値としてコピーします。


## 既定文章の改稿と心の声（v0.18.1）

`personality_wording_version: 1` で今回の文章更新を一度だけ適用します。旧既定の文と同じ性格・話題で完全一致した文章だけを改稿版へ差し替え、編集済みの文章・順序・削除を維持します。「寡黙な先輩」の心の声は、1つのセリフ内の改行と全角括弧で記述する普通の文字列です。別のルールやコードは不要です。[性格の仕様](PERSONALITIES.md)を参照してください。


v0.18.2では先輩の心の声の表示を「…」だけの返事に限定します。`senior_silence_version: 1` が既定文章の移行済みの印です。1つのセリフに `…`、改行、`（心の声）` と記述します。通常の発言の後に書いた心の声は、保存内容を保持して実表示時だけ除きます。


v0.18.3の `debtor_style_version: 1` は、孤高の債務者の体言止め・倒置法への既定文章の更新済みの印です。対応表は `companion/assets/dialogue/debtor_style_v1.json`。旧既定と完全一致した文章だけを更新します。


## 割合と残りの予定（v0.19.1）

`metric_ratio` は分子・分母・分母の最低計測量・下限と上限の%で指定します。`extended_context_version: 1` は12話題を追加済みの印です。[初期値と形式](EXTENDED_LOGIC.md)を参照してください。

`display_timing_version: 1` は表示時間の移行済みの印です。旧初期値の60秒だけを20秒へ一度変更し、独自に設定した秒数・文章・条件を保持します。容量に余裕がなく印を追加できない場合は、既存の文書を使える状態を保ちます。
