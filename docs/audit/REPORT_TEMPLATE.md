# 専門監査報告テンプレート

- 実行ID / モード / 役ID・担当分野：
- 対象版・絶対パス・SHA256 / 基準版・差分：
- 採用した仕様と受入条件：
- 環境 / 利用ツール / 実際の独立性：
- 実施した範囲 / 未実施の範囲：

## 確定・疑いのある指摘

各項目に以下を必ず記載する。

- ID：担当役のprefix + 連番
- タイトル / 分野 / 重大度P0–P3 / 確度：
- 根拠：ファイル:行、関数、仕様、ログの場所
- 前提・再現条件：版、入力、設定、操作順
- 再現手順・実行コマンド：
- 期待結果 / 実際の結果 / 影響：
- 改善案（実装しない）：
- 検証済み範囲 / 未検証・反証・制約：

## 実行記録

| 対象版 | テスト/条件 | コマンド | 終了コード | 成功/失敗/中断/未実行 | 証拠パス |
|---|---|---|---|---|---|

本数・ケース・アサーション・再実行は別記する。既存試験と独自追加試験を区別する。

## 改善・新機能提案（不具合と分離）

| 提案 | 利用者・課題 | 効果 | 規模/依存 | リスク | 検証方法 |
|---|---|---|---|---|---|

## 未検証・残存リスク

実機/外部連携、仕様不足、入力範囲、ツール不在、未再現の疑いを明記する。

## 統括報告への追記項目

- 12分野または6グループの実施/未実施表。
- 重複指摘ID→統合ID・根本原因・元の証拠の対応。
- 矛盾・追加検証・採用根拠・却下根拠。
- 修正後監査では元指摘ごとの「解消確認 / 再現継続 / 新規副作用 / 未検証」。
- 原本の前後差分/ハッシュ確認。
- 残存リスク、完成判定と根拠・条件。
- 製品修正を行っていないこと。
